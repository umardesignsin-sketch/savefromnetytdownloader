# SaveFromNet SEO and reference architecture audit

Audit date: 2026-10-07. Reference: [VidsSave](https://vidssave.com/), its [public sitemap](https://vidssave.com/sitemap.xml) and [robots.txt](https://vidssave.com/robots.txt). Target: [SaveFromNet](https://savefromnet.fun/). This is an information-architecture comparison. No reference code, styling, copy, assets, or branding was reused.

## Scope and evidence

- [reference-url-gap.csv](reference-url-gap.csv) inventories **1,121 discovered reference URLs**: 906 from the public sitemap and 215 additional links found on its main English pages. The sitemap supplies 863 localized path URLs. The root-language pages were fetched to inspect status, destination, and canonical; localized and linked-only URLs are listed as discoveries, not asserted to be live or indexed. The related-URL column is a sample of links found on each inspected page, including navigation links, rather than an editorial relationship claim.
- [savefromnet-url-inventory.csv](savefromnet-url-inventory.csv) lists every canonical route in this build with its status, title, H1, and canonical URL. There are **44 indexable public pages**: 1 homepage, 25 tool pages, 10 guides, 1 guide hub, and 7 new directory/trust pages.
- The Search Console screenshots supplied by the owner show **three-month query totals**, but not the corresponding Pages table. They do not identify which URL earned each query's clicks. The current ranking URL for each query is therefore **unverified**. Position is visible only for the first filtered query. Do not infer landing pages from a public search result.
- Tests and local rendering can verify implementation, not Google's current index or a source platform's willingness to serve media from the production container.

## Existing product before this change

SaveFromNet uses Flask for local rendering and the JSON API. `generate_static.py` renders pages for Cloudflare Worker static assets; a Cloudflare Container runs Flask, yt-dlp, gallery-dl, and ffmpeg for on-demand analysis and downloads. The detector allowlists URL patterns for YouTube, Instagram, TikTok, Facebook, Pinterest, Reddit, Threads, and Dailymotion. A shared analysis result provides only returned formats. A background job creates temporary files; browser-bound signed links expire after 15 minutes. Worker and Flask rate limits apply. Local SQLite stores temporary job history and aggregate events; Cloudflare Analytics Engine stores aggregate events. Google Analytics is also installed sitewide. There is no customer authentication or permanent media database.

Before this change, the public sitemap had 37 pages: home, 25 tools, 10 guides, and the guide hub. Each had a canonical and route-specific title and description. Tool pages had WebApplication, FAQPage, and BreadcrumbList JSON-LD; guides had Article, FAQPage, and BreadcrumbList. The sitemap listed canonical public pages; robots.txt excluded `/api/`. Existing routes were kept.

## Reference architecture and gap decisions

VidsSave's main navigation covers YouTube variants, Instagram variants, TikTok, Facebook, Pinterest, Reddit, Threads, and Dailymotion. Its footer links guides, policy pages, regional pages, and browser-extension pages. Some reference sitemap URLs redirect to separate Instagram or TikTok domains; two YouTube-video routes target nearly the same intent. Its public robots file includes a broad root disallow, which is not an indexing model to copy.

SaveFromNet already has functional canonical tools for all eight supported platforms and the main format intents. The mapping CSV marks 28 discoveries implemented directly and 26 consolidated into existing or new canonical pages. X/Twitter and its GIF variant are **not technically supported** by the current detector or extractor and were not advertised as working pages. Browser-extension pages were omitted because no extension exists. The movie-topic page is unrelated to a general downloader. Untranslated language and region pages were omitted; automatic translation without localization QA would create low-value pages. Additional linked aliases were not turned into new pages merely because they appeared in navigation.

## Changes made in this build

- `/tools` uses a structured directory of the **25 existing working tool routes**, grouped by use. A format note explains that actual choices are returned after analysis. No unsupported tool card or fake result was added.
- `/about`, `/contact`, `/privacy-policy`, `/terms`, `/dmca`, and `/copyright` share site navigation and footer. Their copy describes the actual temporary processing model. `/dmca` provides a report channel without claiming an unverified U.S. Copyright Office designated-agent registration.
- The existing `/youtube-to-mp3` page gained a distinct workflow, audio-quality explanation, troubleshooting, device guidance, and specific FAQs. The homepage gained branded MP3 guidance and contextual links to supported converter pages. No new brand-keyword URL was launched.
- Canonicals, unique titles/descriptions, H1s, BreadcrumbList plus appropriate page-type JSON-LD, sitemap entries, and internal links are generated from centralized data. The 404 page remains HTTP 404 and now contains `noindex`.
- `tool_page_view`, `download_started`, and `download_failed` aggregate events complement the existing analysis, format-selection, click, and completed-download events. Event payloads do not contain submitted URLs.
- Cloudflare static `_headers` adds clickjacking, MIME-sniffing, referrer, and browser-permission protections. robots.txt additionally excludes health and service-worker paths; API, health, and service-worker responses receive `X-Robots-Tag` from Flask when served there.

## Sitemap and linking

The single `/sitemap.xml` is sufficient for 44 pages and includes only canonical public routes. The homepage links to `/tools`, MP3 converters and guides. The tools directory links every actual downloader; platform/tool pages link related tools and guides; trust pages link each other and the directory. Footer links make all new pages reachable. API endpoints, temporary download URLs, 404s, and query variants are absent from the sitemap.

## Intentional omissions and remaining limits

- No `/save-from-net-mp3` or `/savefrom-mp3-converter` until query-filtered Search Console Pages data identifies the existing URLs earning those clicks. No generic `/mp3-downloader`, `/mp4-downloader`, or extra format aliases were added because they overlap current converter and universal intents.
- No X/Twitter, Vimeo, Twitch, Snapchat, browser extension, country, or language landing page: corresponding functionality or original localization is not in the current product.
- No new blog pages just to increase URL count. Existing practical guides cover real supported behavior.
- Source platforms can remove posts, block data-center traffic, demand sign-in, or change formats. The 512 MB processing ceiling and temporary container storage remain. A live end-to-end check using Blender's public Big Buck Bunny upload completed an MP3 job, served a signed partial-file response (`206`, `audio/mpeg`), and deleted the test job afterward. This verifies one YouTube path, not every source or format.
- The existing advertising script and externally imported service worker remain a third-party performance and security dependency. Their behavior and commercial role require a separate owner review before removal or a strict CSP can be shipped safely.
- Google Analytics currently loads sitewide. Its cookie and regional consent settings need review against the audiences and laws that apply to this service; the new privacy page discloses the tag but cannot determine consent requirements from the repository alone.
- Search Console page attribution, index coverage, Core Web Vitals field data, and ranking movement cannot be verified from screenshots of query totals. The URL inventory records what the site emits, not what Google currently indexes.

## Programmatic content follow-up, 2026-10-07

Fifteen existing tool URLs now render distinct, tool-specific sections from the centralized `TOOL_SECTIONS` registry, with contextual links from `TOOL_SEO_LINKS`. The copy explains accepted link shapes, actual format behavior, and source access limits for the core YouTube, Instagram, and TikTok tools plus high-intent format and platform pages. The shared template renders these records without duplicating page components. Every link resolves to an existing working tool or guide. Titles, canonicals, route paths, and the 44-URL sitemap remain unchanged, protecting the existing MP3 search intents while adding useful detail to existing pages.

## Specific-link and troubleshooting expansion, 2026-10-07

Six new guide URLs were added: `/guides/tiktok-photo-posts`, `/guides/facebook-reels`, `/guides/pinterest-images`, `/guides/video-file-size-estimates`, `/guides/temporary-download-links`, and `/guides/video-with-no-sound`. Each has a distinct question to answer, three substantive sections, specific FAQs, and a working form bound to an existing supported downloader. The first three address supported media/link types; the other three explain real processing behavior that users can act on. No new extractor or unsupported quality claim was introduced. Contextual links from relevant tool pages, the guides hub, the tools directory, and related-guide navigation make the pages discoverable. The sitemap and generated URL inventory now contain **50 canonical public pages**; all 44 pre-existing paths and canonicals are retained. The priority MP3 query URLs remain unchanged because query-to-page attribution is still unavailable.

## Calculator and image-format resource follow-up, 2026-10-07

The existing `/guides/video-file-size-estimates` page now places a working browser-side calculator above its downloader form. It estimates bytes from duration and the combined video/audio bitrates, distinguishes decimal MB from binary MiB, and warns when the estimate exceeds the actual 512 MiB processing ceiling. It explicitly cannot measure a source file or promise the finished size. The 25-minute 19 Mbps example explains why a long 4K upload cannot plausibly be a 23 MB complete file at that bitrate.

`/image-format-guide` is one new canonical resource answering a distinct format-choice question. Its recommendations are tied to the nine existing working image tools and their verified constraints: accepted still formats, white background on JPG output from alpha, lossy output settings, and upload/pixel limits. Every image-tool page and the tools directory link to it; the homepage and footer link to the resource and the calculator. No new converter URL was published without a backend. The generated sitemap and inventory now contain **60 canonical public pages**: 1 home, 25 media tools, 9 image tools, 16 guides, 1 guide hub and 8 directory/resource/trust pages. All 59 previous canonicals remain unchanged.

The local HTML crawl found no duplicate titles or descriptions, no missing H1 or canonical, and no unresolved internal links. A real 390-pixel browser viewport showed no horizontal overflow on either changed resource. PageSpeed Insights returned HTTP 429 during this pass, so no field performance score or ranking improvement is claimed. Search Console query-to-page attribution is still unavailable. The [Search Essentials](https://developers.google.com/search/docs/essentials) and [helpful content guidance](https://developers.google.com/search/docs/fundamentals/creating-helpful-content) favor useful original material over a large set of keyword-variant pages, so the existing high-click YouTube paths and titles were left intact.

## Live crawl and specialized-page follow-up, 2026-10-07

The live sitemap listed 60 URLs at audit time. Every listed URL returned HTTP 200 with a matching HTTPS canonical, a title, meta description and H1. Titles and descriptions were unique, every page had an internal incoming link, and the crawl found no internal link to a page outside the sitemap. The two shortest pages were contact and copyright notices; their length alone is not a reason to inflate them with search copy.

Nine existing specialist downloader pages received task-specific guidance about accepted links, source formats, access limits and adjacent working tools. This completes distinct editorial sections for every current media tool, including the locally in-progress transcript page. No URL, canonical, heading or title was changed. The sitemap now emits only canonical locations; Google ignores the former `priority` and `changefreq` hints, and no unverified `lastmod` dates were invented.

One live technical gap remains outside the site's code: `http://savefromnet.fun/` serves HTTP 200 instead of redirecting to HTTPS. The existing Cloudflare OAuth credential has zone-read scope but receives HTTP 403 for the zone setting API, and the available browser opens the dashboard at sign-in. Enable **SSL/TLS → Edge Certificates → Always Use HTTPS** for the `savefromnet.fun` zone, then verify a 301/308 redirect from HTTP to the same HTTPS path. The current static-asset-first Worker cannot reliably redirect those requests without running the Worker for every asset, which would add billable requests and latency.

Search Console index coverage, query-to-page attribution and Core Web Vitals field data remain unverified. This release should be measured after deployment; do not claim that content additions or sitemap cleanup guarantee higher rankings.
